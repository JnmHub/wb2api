# v2.4.4 修复 11128 渠道校验拦截（DSH @ 路径段落指纹）

这一版只有一个目的：让 DeepSeek Harness 的请求重新通过上游渠道校验。

## 问题

2026-10-27 起，CN 池对 DSH 会话的请求统一返回：

```json
{"code": 11128, "msg": "Illegal API invocation from an unapproved channel"}
```

网关对外表现为 HTTP 400、`type: invalid_request_error`，文案是
`upstream 400: content rejected by upstream policy (code 11128)`。
换模型、新建会话、升级中转版本都无效，国际池不触发。

## 根因

上游渠道 WAF 维护了一份「官方客户端特征串」清单，第四轮加进来的特征，是官方客户端注入到
system prompt 里的 **`@` 路径说明整段原文**：

```
Tokens prefixed with @ are paths the user explicitly referenced. Relative paths resolve
from the workspace root; ... The @"..." form only quotes a path that contains spaces.
```

网关原有的脱敏规则只覆盖三类旧特征：自我介绍句、`DeepSeek Harness` 品牌词、裸 header。
这段较晚才进入 DSH 系统提示的段落不在规则里，于是原样带出 → 命中特征 → 400 / 11128。

这也解释了「为什么只针对 DSH」：那句话是 DSH 官方模板独有的，其它客户端没有。

## 修复

`internal/gateway/shape/sanitize.go` 增加一条规则，把该段**同义改写**（不删除、不改语义）：

- 新增指纹 `sanitizeDSHPathsNeedle`，挂进 `sanitizeFeatures` —— 只有真正命中才走脱敏路径，
  其它请求不产生额外开销；
- 新增 `sanitizeDSHPathsRe`（`(?is)…{0,900}?spaces\.`，覆盖官方原文与本地构建措辞两种变体）；
- 在 `sanitizeBase` 末尾替换为等义表述，`@` 语义、相对/绝对路径、结尾斜杠、read tool、
  含空格引号全部保留，只改措辞。

改写后模型行为不变，上游特征串不再连续命中。

## 验证

- `go test ./internal/gateway/shape/` 通过，新增 3 个用例：两种措辞都被改写、改写幂等、
  段落前后的 prompt 与工作目录不丢、段落单独出现也能进入脱敏。
- 用真实抓到的 DSH system prompt（33 KB，含脱敏开关说明与整段越狱块）过
  `sanitizeSystemText`：输出无残留指纹，其余内容完整。
- 清洗后的文本原样 `POST https://<relay>/v1/chat/completions`（`deepseek-v4.1-flash`，`stream=true`）
  返回 **200**；清洗前同一段为 11128。
- `go vet ./...` 干净，`go test ./... -count=1 -p=1` 全量通过。

## 升级说明

- 无需改配置、无需数据库迁移；更新二进制（或镜像）后重启即可生效。
- 同一份 system prompt 第二次经过脱敏不会再次变化（幂等），不会因为多次重试而漂移。
- 该修复只影响 `system` / `developer` / `assistant` 文本内容；`user` / `tool` 内容保持原样。

## 已知边界

- 上游对「官方客户端原话」的态度是持续收紧：自我介绍句 → GUI 段 → 品牌词 → `@` 路径段，
  这已经是第四轮。若后续出现新的 11128，优先怀疑系统提示里又多了新的官方模板段落，
  按同样方式加一条指纹即可。
- 该规则只做措辞改写，不伪造渠道身份，也不改变请求的其它字段（模型、工具、采样参数原样透传）。

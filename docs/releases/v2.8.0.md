# v2.8.0 — 身份列不再显示 workbuddy；新增账号推送接口

两个都是部署时立刻会碰到的：面板上一个显示错的列，和一条只能靠浏览器点出来的导入路径。

## 1. 「身份」列对华为账号不再显示 workbuddy

`身份` 列原本直出账号记录里的 `product` 字段。那是 WorkBuddy 的**出站身份**
（desktop / vscode / cli），华为渠道根本没有这个概念——导入时该字段缺省成
`workbuddy`，于是整列都显示成 `workbuddy`，看着像是"所有华为号都挂着一个
WorkBuddy 身份"。

现在华为渠道这一列显示 `—`，与账号详情里「出站身份」已经隐藏的行为一致
（`AccountDrawer` 早在 v2.6.x 就按渠道隐藏了，只有表格漏了）。

WorkBuddy 账号的显示不变。

## 2. 账号推送接口：`POST /api/v2/accounts/push`

面板的导入需要浏览器会话 + CSRF 头，自动化（登录机器人、另一台网关、cron）
根本用不了。新增的接口用 **API key** 认证，直接把账号推进池子：

```bash
curl -X POST "http://服务器:8080/api/v2/accounts/push" \
  -H "Authorization: Bearer $KEY" -H 'Content-Type: application/json' \
  --data-binary @account.json
```

- 接受四种形状：`{"accounts":[...]}`、裸数组、单个账号对象、面板导出文件原文
- 同 `uid` **覆盖**（重新登录机器人的语义），不会重复添加
- `?dry_run=1` 只校验不落盘
- 返回 `added / updated / skipped / invalid`，`invalid` 带行号与原因
- 认证：有 key 就必须带；没配 key 时**只放行本机环回**，公网一律 401
  （写接口不能因为"还没配 key"就对外敞开）

完整字段说明见 [docs/PUSH_API.md](../PUSH_API.md)。

# v2.5.1 — 提示词净化可调，思考截断给出可操作错误

两个都是"被上游拒绝时到底该怎么办"的问题：一个是内容审核把客户端身份句当指纹，
一个是思考把输出预算吃光却只回一句看不懂的报错。

## 内容审核：净化改成三档，且不再整段替换

上游内容审核会把**客户端身份句**当指纹匹配，命中就整条拒掉（`code 11-128`）：

- Codex：`You are a coding agent running in the Codex CLI tool, a terminal-based coding assistant.`
- Claude Code：`You are Claude Code, Anthropic's official CLI tool for Claude.`
- DSH：`You are an AI assistant built on DeepSeek Harness.`

原来的兜底是"命中 403 就把整个 system prompt 换成中性提示词"，代价是模型丢掉
「什么时候用哪个工具」的约束。这一版把改写做成**可配的三档**，默认档只动身份句：

| `prompt.sanitize` | 行为 | 代价 |
| --- | --- | --- |
| `identity`（默认） | 只把身份/厂商句换成中性句，工具契约、工作流规则、`@` 路径段落**逐字保留** | 几乎无 |
| `full` | 整段 system prompt 换成中性提示词（等价于原 403 降级） | 丢客户端行为约束 |
| `off` | 不做结构化改写，只保留原有最小改动指纹补丁 | 可能继续撞审核 |

`identity` 的实际改写：

```
You are a coding agent running in the Codex CLI tool, a terminal-based coding assistant.
Codex CLI is an open source project led by OpenAI.        →  You are a coding assistant.
You are Codex, based on GPT-5.                             →  （删除）
You are Claude Code, Anthropic's official CLI tool for Claude.  →  You are a CLI coding assistant.
You are an AI assistant built on DeepSeek Harness.         →  You are a helpful AI assistant.
```

作用范围：system / developer，以及被上游回显校验的 assistant 历史；**user 与 tool
内容不动**。`full` 也只替换 system/developer，重放的历史仍保留正文，只丢身份句。

配置（面板「设置 → 上游与提示词」有下拉框）：

```json
{"prompt": {"mode": "passthrough", "file": "", "sanitize": "identity"}}
```

```bash
curl -X POST localhost:8788/api/settings -H 'Content-Type: application/json' \
  -d '{"prompt": {"sanitize": "identity"}}'
```

## 客户端侧：只改身份句（文档）

新增 [docs/PROMPT-SANITIZE.md](../PROMPT-SANITIZE.md)：Codex / Claude Code 各一句的
改法、system prompt 自检清单，以及"单发你好 → 加完整 system → 二分定位"的排查流程。
适合改得了客户端、又不想让网关改写任何内容的场景。

## 思考截断：错误里写清原因

`upstream returned reasoning without content` 现在会在 `finish_reason=length` 时附上处置建议：

```
upstream returned reasoning without content (finish_reason=length: the max_tokens budget
was consumed by thinking; raise max_tokens, lower reasoning_effort, or use a model that
can disable thinking)
```

原因很常见：国内目录 39 个模型里 29 个是 `onlyReasoning`（思考默认开，多为 `high`），
而网关把客户端的 `max_tokens` 原样转发——预算偏小就被思考吃光，正文一个字都没有。
四个抛出点（chat 流式 / chat 非流式 / responses 流式 / responses 非流式）都会带上
真实 finish 原因。

## 回归测试

- `TestIdentityStrengthNeutralisesClientIdentity`：Codex 三句 + Claude Code 句被中性化，
  `Use the shell tool for commands…` 契约逐字保留。
- `TestOffStrengthLeavesIdentityAlone`、`TestFullStrengthReplacesSystemPrompt`：
  off 不动文本；full 只换 system/developer，user 内容不变、assistant 仅丢身份句。
- `TestReasoningOnlyNamesTheBudgetWhenTruncated`：截断时带 `max_tokens` 提示，
  `stop` 与空 finish 保持短文案。
- 设置层：`sanitize` 默认 `identity`、大小写归一、非法值拒绝。
- golden 向量中 2 条含身份句的期望输出已按新行为更新。

## 升级说明

- 无需迁移，配置文件不用改。
- **默认档位是有行为变化的**：`identity` 会比旧版更彻底地中性化 Codex / Claude Code
  身份句（旧版只做"插一个词"的最小改动补丁）。这正是被拦的原因，属于有意的修复；
  若你要出站文本与旧版完全一致，把 `prompt.sanitize` 设成 `off`。
- 未包含：`400 + 审核码` 仍不会触发自动降级重试（目前只认 403）；审核命中暂不记录
  命中了哪条指纹。这两项留到后续版本。

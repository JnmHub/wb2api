# v2.6.0 — 第三个渠道：华为云 CodeArts（盘古 / 码道）

这一版把「渠道」从两个 WorkBuddy 出口扩成三个：新增 `realm=codearts`，
华为云 CodeArts Agent 的账号进同一个池，走同一套三协议入口、选号、冷却、
Key 白名单和用量账本。

WorkBuddy 的两个出口行为不变，没有迁移，也没有默认值变化。

## 渠道是什么

`realm` 从此表示**渠道**而不是「地域」，取值 `intl` / `cn` / `codearts`：

| 渠道 | 上游 | 鉴权 | 账号文件 |
| --- | --- | --- | --- |
| `intl` | `www.workbuddy.ai` | Bearer + 客户端身份头 | `data/accounts/<uid>.json` |
| `cn` | `copilot.tencent.com` / `www.workbuddy.cn` | 同上（国内 UA/设备令牌） | 同上 |
| `codearts` | `snap-access.cn-north-4.myhuaweicloud.com` | `x-auth-token` + 华为云 SDK-HMAC-SHA256(AK/SK) + DPoP 续期 | 同上，凭证在 `extra.codearts` |

按 Key 绑定渠道、`X-Realm` 头、`?realm=` 三种选法都支持；未指定时跟随面板当前渠道。

## 请求链路

- **签名**：`SDK-HMAC-SHA256`，全头签名（`X-Sdk-Date` / `X-Security-Token` /
  `X-Sdk-Content-Sha256`），canonical URI 补尾斜杠、SignedHeaders 排序——按官方 SDK 规则实现，
  有固定向量测试（向量由独立 Python 实现算出）
- **请求体**：白名单裁剪成上游认得的字段，强制 `stream: true`（上游只有流式），
  非流式客户端由网关聚合
- **不压缩**：签名覆盖的就是线上字节，gzip 会让 payload hash 对不上
- **错误语义**：
  - `InferHub.001001005`（参数错）→ 原样 400，不换号、不冷却
  - `InferHub.002002009` / `TM.000010051` / `4004.200`（未注册 / 无权 / 福利未领取）→ 只给该模型 30 分钟冷却，继续换号
- **续期**：OAuth2 `refresh_token` + DPoP（`codearts-agent` client），终态失效转「需要重新登录」
- **模型目录**：三源并集（agent-center / builtin / 福利网关），福利模型自动带 `maas_type: benefit` 头

## 模型自动发现与福利

后台扫描按账号每 30 分钟刷新一次目录（`models` / `benefit_models` / `models_at` 写回账号记录），
启动时先跑一轮。三源任一失败只记录原因，不阻断其余来源；全部失败时保留上一轮目录，
不会把 `/v1/models` 清空。

限时福利模型需要先「领取」（上游幂等，官方客户端打开模型菜单也会调），默认自动领取，
不想让网关写账号就 `WB_CODEARTS_BENEFIT_CLAIM=0`。

面板「模型」页在 CodeArts 渠道下有「重新发现」按钮，`POST /api/v2/codearts/models/refresh`
可指定单个账号或整个渠道。

## 登录

不需要回调端口：面板（或 API）生成 ticket + PKCE + DPoP，打开门户链接，
网关轮询 `snap-manager/v1/login/ticket` 取凭据，成功后自动建号并立刻拉一次目录。

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| POST | `/api/v2/accounts/login/start` | `{"realm":"codearts"}` → `{state, authUrl}` |
| GET | `/api/v2/accounts/login/poll?state=` | `pending` / `ok` / `error` / `expired` |
| POST | `/api/v2/accounts/login/cancel` | 丢弃未完成的登录 |

面板「添加账号」的渠道下拉里选「华为 CodeArts」即可，登录身份（CLI/VSCode）对该渠道不适用。

## 签到

CodeArts 的签到是**领积分**（每日 1000，活动 1 / 新手活动 4），与 WorkBuddy 的
签到+成长任务+猫猫旅行是两套东西：

- 面板「签到」按钮（单账号动作与批量都按账号渠道分派）
- 调度器新增渠道钩子，按 `checkin` 整点表自动跑，汇总行新增「华为签到 N」
- 状态机是「投放 → 领取 → 确认」，已领取只补确认，不重复领取；结果写进账号的 `last_checkin`

## 并发按渠道

两个厂商的容量模型不一样：WorkBuddy 一个账号能跑十几条，CodeArts 三条左右就开始回推。
全局 `-per-account-inflight` 一个数字满足不了双方，所以这一版加了一层取小：

| 全局 | CodeArts 实得 |
| --- | --- |
| 0（不设） | 3 |
| 1 | 1 |
| 8 | 3 |
| 8 + `WB_CODEARTS_INFLIGHT=5` | 5 |
| 8 + `WB_CODEARTS_INFLIGHT=0` | 8 |

本地闸门和 Redis 共享闸门读同一个值，不会出现「本地放行 3、Redis 放行 8」。
账号占满时请求在本地换号/排队，不会把第 4 条并发打到上游。

## 面板

- 渠道下拉、账号筛选、Key 绑定、请求页筛选都多了「华为 CodeArts」
- 账号标签用金色区分；抽屉里该渠道隐藏「刷新积分」和「出站身份」（都不适用），保留「签到」
- 模型页支持渠道切换与「重新发现」

## 顺带修的

- **配额巡检不再碰 CodeArts 账号**：`quota.Scanner` 的 watched model 属于 WorkBuddy，
  拿这些 id 去探华为上游只会拿到 404 并污染看板
- 登录轮询把上游业务错误（如 `APIG.0201`）当错误返回，不再伪装成「还在等」

## 已知边界

- **成本估算**：价格表仍是 WorkBuddy 口径，CodeArts 模型成本显示 0，token 数是真数
- **真机未验收**：签名、模型 ID、福利领取、门户登录、并发 3 都是从参考实现与实测默认值推的，
  本版只在 fake 上游上验证；拿真实账号跑一遍 `docs/CODEARTS_CHANNEL.md` §9.7 的清单更稳妥
- **账号校验接口**（`current/user`）协议层已实现，面板没有单独按钮
- 签到只做活动 1 和 4，其他活动不参与

## 升级说明

- 不需要迁移，配置与账号文件都不用改；WorkBuddy 渠道行为完全不变
- 新渠道是**可选**的：没有 `realm=codearts` 的账号时，所有代码路径与 v2.5.1 一致

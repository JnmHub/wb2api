# v2.4.7 — 「清除冷却」现在真的能把账号救回来

发布日期：2026-10-29

## 背景

v2.4.6 把 429 `14018`（额度已用尽）从「60 秒模型窗口」改成「park 到次日 04:00」。
这是对的，但带出一个副作用：面板上的「清除冷却」只清账号级软限流计时器和模型窗口，
**没有清 402 / 429 额度耗尽使用的 `balance` 计时器**。于是运营点了「清除冷却」，
账号仍然显示冷却中，直到 04:00 或积分刷新读到余额为止 —— 按钮看起来坏了。

## 修了什么

`internal/pool/view.go` 的 `ClearCooldowns` 现在清掉全部本地计时器：

| 计时器 | 来源 |
|---|---|
| `cooldown` | 429 软限流阶梯 |
| `modelCool` | 单模型 60 秒 / 6004 窗口 |
| `breaker` / `degrade` | 5xx、客户端断连熔断（30 min→6 h） |
| `balance` | 402 与 429 额度耗尽，park 到次日 04:00 |

同时清空「最近错误」（所以面板不再显示旧的上游报错）。
风控标记（`restricted`）仍然只在「解除风控」动作里清除 —— 那是另一件事，不能顺手抹掉。

## 不变

- 自动恢复的路径不变：积分刷新读到 `remain>0` 会自动解除 park（`ReviveBalanceCooldown`）；
- 「清除冷却」只清本副本的内存状态，不动账号文件里落盘的 `model_caps` / 风控时间；
- 真正的额度耗尽账号，清完冷却后下一次请求会被上游再回一次 14018、再 park 一次 ——
  这是正确行为，不是回归。


  清冷却后立刻 `Ready()==true`、`State()==ready`。

# v2.4.8 — 模型冷却看得见、接得上、跨副本一致

这一版围绕「一个模型被打满时会发生什么」做了三件事：让面板块说清楚是哪个模型在冷却、
在全部账号都被这个模型挡住时自动沿后备链换模型、以及把模型级冷却在多个副本之间共享。

## 更新内容

1. **模型冷却可视化**
   - 账号行/详情里每个受限模型都带原因：`上游限流`（429 阶梯）、`额度窗口`（6004/免费额度）、
     `无权限`（11158）、`其他副本`（共享窗口）、`手动`。
   - 新增 `GET /api/v2/models/cooldowns`：按 `realm + 模型` 聚合冷却账号数、仍可用账号数、
     最早/最晚解除时间与原因分布；「模型」页面直接以「模型冷却」表格展示，5 秒刷新。
   - 原因随账号记录一起落盘（`modelCoolWhy`），重启后仍然可见。

2. **模型后备链（阶段式）**
   - 新设置 `model_fallbacks`：`{"deepseek-v4.1-flash": ["space-bunny", "glm-4.7"]}`，最多 8 段，
     配置来自面板「设置 → 模型路由」。
   - 触发条件是**当前模型在所有账号上都不可用**（限流窗口、额度窗口、失去权限，或账号本身
     停用/受限/无积分）；还有任意一个账号能服务时就原地等待/重试，不做「按账号换模型」。
     一次请求最多沿链走一遍，链上同样不可用的模型会被跳过，已被封锁名单过滤的模型不会进入链。
   - 返回体的 `model` 始终是**客户端请求的名字**，三个协议（Chat / Responses / Messages）一致；
     用量与计费仍按真实服务模型记录，日志里能看到 `model` → `next` 的换模型记录。
   - 别名与链可以叠加：别名先解析成真实模型，再按真实模型查链。

3. **模型窗口跨副本共享（Redis）**
   - 配置 Redis 时，模型级冷却写入 `wb:mcool:<realm>:<model>`（member = 账号 UID，score = 解除时间）。
   - 每个副本在读请求前拉一次候选账号的窗口（1 秒缓存，单次 pipeline，900ms 超时），命中即
     就地生成同样的冷却，面板、选号与健康复查三处口径一致；成功调用会清掉共享窗口。
   - Redis 不可用时不缓存错误、直接按本地状态继续，不影响请求。

## 升级说明

- 不改变任何已有配置的默认行为：没有配 `model_fallbacks` 时完全沿用单模型逻辑。
- 共享窗口默认启用（仅在配置了 Redis 时生效），无需新增环境变量；若要完全回到单机状态，
  不配置 Redis 即可。
- 模型链是「兜底」而不是「负载均衡」：它只在当前模型彻底不可用时触发，不会因为某个账号
  慢一点就把请求换到别的模型。

## 下载与校验

每个发行版附带 `wb2api-linux-amd64`、`wb2api-linux-arm64` 及各自的 `.sha256`。
下载后先校验再运行：

```sh
sha256sum -c wb2api-linux-amd64.sha256
```

仍按原有方式部署（Docker Compose 从源码构建，或直接运行发行版二进制）；升级时保持数据目录与
每个副本独立的 outbox 不变，不要 `docker compose down -v`。

# v2.6.2 — 闲置两小时后签到/发现直接报 APIG.0602

CodeArts 的 STS 凭证只有 ~2 小时。对话路径有「401 → 续期 → 重试」，签到和模型发现
没有，于是账号放两小时再点「签到 / 测活」，面板上就是一条原始报文：

```
codearts /v1/ops/delivery HTTP 400:
{"error_code":"APIG.0602","error_msg":"Bad request: the security token has expired"}
```

v2.6.0 / v2.6.1 都有这个问题（报告按 v2.6.0 提的；v2.6.1 未改这两条路径）。

## 根因

三条路径各自直接取记录里的 STS，既不临期先刷，也不在过期后补救：

- `codeartsync.Discover` → `codearts.CredentialOf(rec)` 直接用于三源发现
- `codeartsync.Checkin` → 直接用于 `/v1/ops/*`
- `refresh.due()` 在 `ExpiresAt == 0` 时 `return false`：导入或手写的账号**永远不会**被后台刷新

后台 Refresher 提前 15 分钟刷通常能覆盖，但有三个窗口期会漏：进程刚起首轮扫描未完成、
账号刚登录/导入时过期时间已落在窗口内、以及上面那种没有过期时间的记录。

## 修复

**1. 用前先续期。** `codeartsync.Service` 新增 `Refresh` 钩子（`main` 里接
`refresher.Refresh`）和 `Lead`（默认 10 分钟）：

- `Discover` / `Checkin` 进入时若凭据「已过期或剩余不足 Lead」，先续期再用
- 续期失败**不丢旧凭据**，继续用现有 token 尝试——一次续期失败不该把能用的令牌变成不能用

**2. 过期后补一次。** 上游回 `APIG.0602` / `security token has expired` / `401` 时，
续期一次再重试一次（只一次，避免死循环）：

- `Checkin`：`codearts.IsExpiredCredentialError(err)` → 续期 → 重试
- `Discover`：三源结果里任一命中同一判据 → 续期 → 整体重跑一次

**3. 没有过期时间也会被刷新。** `refresh.due()` 对 CodeArts 渠道的 `ExpiresAt == 0`
改为「试一次，失败后退避」，与「缺 token」同规则；WorkBuddy 行为不变。

**4. 面板文案。** 续期后仍然过期时，写入 `LastCheckin.message` 的不再是原始报文，而是
「凭据已过期，自动续期未成功（需要重新登录该账号）」。

## 测试

```
ok  internal/codeartsync   过期后先续期再签到；0602 触发续期并重试成功；发现路径同样重试
ok  internal/refresh       CodeArts 无过期时间→可刷新、失败后回退；WorkBuddy 行为不变
ok  internal/api / upstream/codearts / scheduler / ops / quota / realm
```

单测用 `X-Security-Token` 头区分新旧令牌：旧令牌一律回 0602，续期写入新令牌后重试才放行。

## 报告里复现步骤的对照

| 场景 | 现在 |
| --- | --- |
| STS 自然过期后点签到 | 先自动续期，再签到 |
| 续期也失败（refresh_token 失效） | 面板显示「需要重新登录」，不再是 0602 报文 |
| `ExpiresAt` 缺失的导入账号 | 后台扫描会尝试刷新，不再永久跳过 |
| 登录/导入后立刻点签到 | 临期检查覆盖，不会撞窗口期 |

## 升级说明

无需迁移。已经导入过、`expiresAt` 为空或过期的 CodeArts 账号，升级后首次扫描会自动补一次续期。

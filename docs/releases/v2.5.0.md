# v2.5.0 — 国内成长任务引擎对齐上游，桌面对话链真正点亮

这一版的成长任务模块是照着 legacy Python 的 **v1.7.16** 快照移植的，而上游在
**v1.10.4** 把整个引擎重写过：新增小程序链式任务、动态专家解析、资料库埋点、
成长能量开盲盒，并且把「桌面对话（RichMeow_Chat）」和「资料库（Library_read）」
从「只能桌面端手动做」改成可以用埋点点亮。本次把这一整轮补齐，另外用真实账号
对着上游验证了其中最容易出错的一条链。

## 修复：两个任务此前直接跳过

- **桌面对话（`RichMeow_Chat`）** 和 **浏览资料库（`Library_read`）** 在原移植里被
  标成 `desktop: true`，`progressTask` 命中就 `return 0`，一条事件都不发 —— 等于每天
  白丢 200 积分。现在：
  - `Library_read` 上报官方文档的 `web_element_click`（`pageURL` + `elementId`）。
  - `RichMeow_Chat` 上报 6 连桌面会话链：创建任务 → 发消息 → 发请求 → 收消息 →
    请求结束 → 任务完成，共用同一个 `conversationId`，时间戳依次 +20/40/60/80/100ms。

## 关键发现：光发事件链不够，必须带桌面设备信封

上游 v1.10.4 的 Python 实现只发那 6 条事件，**实测进度永远停在 `0/1`**（它自己的
日志里也是 `已上报但进度 0/1 未达成`）。用真实账号做变体探测后确认：

| 变体 | 上游返回 | 进度 |
|---|---|---|
| 一条 POST 发 6 事件数组（Python 做法） | `code=0` | 0/1 |
| 6 条拆成 6 次 POST | `code=0` | 0/1 |
| **每条事件补桌面设备信封** | `code=0` | **1/1 completed** |

信封字段：`product` / `ideType` / `ideVersion` / `extName` / `extVersion` / `ideName` /
`platform` / `os` / `osVersion` / `arch` / `machineId` / `timezone`。缺了它，采集侧
只当成一条匿名埋点收下，不认作桌面会话 —— 所以照抄 Python 的链在这个任务是无效的。
`machineId` 取账号自己的设备指纹（`fingerprint.MachineID(uid)`），不硬编码。

## 新增：微信小程序链式成长任务

`/v2/activity/growth/tasks` 在小程序口径下会多出 `Sequential_Tasks_1~6` 与
`school_season`，接取 / 上报 / 领奖都要带小程序身份：

- 查询、接取、领奖：`X-Client-Platform: miniprogram` + MicroMessenger UA。
- 事件上报：`X-Client-Product: workbuddy-mp`、`X-Client-Platform: mp-weixin`、
  `X-Platform: wechatmp`，事件体带 `WorkBuddy_MP` 埋点指纹与
  `codebuddy.session_id` / `codebuddy.conversation_request_id`。
- 链式任务会按上游的 `task locked until <日期>` 逐日解锁，未解锁的现在会在日志里
  说明原因，不再静默跳过。

## 新增：动态专家任务与固定专家 ID

- 未预录入的专家任务（`expert_use_*`，或 `jump_url` 里带 `deeplink` + `expertId`）
  现在会自动解析真实专家 ID 并上报 `expert_actual_use`，不再当未知任务静默丢弃。
- 补上固定专家：工作台搭建师、中国电商运营专家、抖音策略师、商家宣传页与海报设计师、
  直播电商教练；`WorkBuddy_Valorant` 改为规格里的固定专家而不是 kind 特判。
- 灵感案例（`playbook`）改成官方口径的**两条**事件：`playbook_cta_click` →
  `playbook_prompt_send`。只发后者不会推进进度。

## 对齐：接取、等待与收尾

- 批量接取后**复核并补接一次**；仍未接取的任务不再上报（上游对未接取任务的事件不计进度），
  并在日志里点名。
- 已 `completed` 的任务一律先结算再谈别的（桌面端/夜间/上一轮顺手点亮的不再丢奖励）。
- 领奖等待改成和 Python 一致：先快查，只有进度确实在涨才继续等，避免每个卡住的任务空等。
- 一轮结束前补上成长能量开 Buddy 盲盒（`buddy/quota` → `buddy/open`），旅行领奖后
  自动开盒再派出新一轮。

## 实测

用真实国内版账号跑完整流程（18 个任务）：**16 个领奖成功、+1406 积分**，余额
1495.18 → 2898.16。剩下的 3 项分别是「进桌面端发现应用」（要真实 GUI 操作）、
「关注公众号满 24 小时」（无接口）、以及一个 `task locked until` 次日才解锁的小程序
链式任务。

命令行复跑（不经面板）：

```sh
go run ./tools/growthrun -file accounts.json -work ./run -dry   # 只看任务状态
go run ./tools/growthrun -file accounts.json -work ./run -all   # 跑一轮
```

## 回归测试

- `TestRichMeowChainIsSixLinkedEvents`：6 条事件的顺序、同一会话、时间戳单调，并且
  **每条都带桌面设备信封**（少了就回到 0/1）。
- `TestLibraryReadSendsTheDocumentClick`、`TestPlaybookSendsBothEvents`。
- `TestDynamicExpertTaskIsReported`：未登记的专家任务能从 deeplink 取到 ID 并上报领奖。
- `TestUnacceptedTaskIsSkipped`：未接取任务不白报。
- `TestMiniProgramTasksUseTheMiniProgramIdentity`：小程序标头、mp 事件体与领奖口径。

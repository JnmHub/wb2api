# v2.4.1 — 会话亲和缓存修复

本版修复一个调度缺陷：**消息数超过 `WB_AFFINITY_MAX_MSGS`（默认 400）的长对话在页内轮转时完全绕过了会话亲和**。这类对话在超限后会跳过亲和读取，每一轮都在所属的页内重新轮转，于是经常落到从未见过该对话前缀的账号上，上游返回的 `cached_tokens` 为 0，首字与整体耗时随之变差。多实例部署中表现为个别实例的「零缓存率」明显高于其他实例，而它们的模型、账号和上游并无差别。

本版还修正了亲和键的取值来源，避免网关侧的 prompt 改写把整个账号池的会话一次性改绑。

## 修复内容

1. **页内优先暖号**：超限对话仍被限制在自己的页（`WB_AFFINITY_PAGE_SIZE`，默认 3）内，以继续分摊超大请求体；但只要该对话的暖号在页内且健康、未被排除，本轮就回到暖号，不再每轮轮转。暖号不可用或不在页内时才在页内换号。换号仍然不会离开该对话的页。
2. **超限对话恢复亲和观察与绑定**：此前只在未超限时读取/发布亲和，超限对话既不读也不写，等于永久冷启动；现在两者对超限对话同样生效。
3. **亲和键改取客户端原始消息头**：键仍由会话前两条消息派生，但改为取客户端发来的原始消息，而不是网关改写后的请求体。切换 prompt 模式（`append` / `custom`）或进入降级窗口时，网关会给所有对话换系统提示，旧实现会因此让全部对话改绑到新账号、整池缓存同时失效；现在不会。
4. **保持既有语义**：客户端提供 `X-Conversation-Id` / `conversation_id` / `metadata.conversation_id` 时仍优先使用；固定账号（pinned）、权重、临期积分、剩余额度偏好、满载等待、故障换号逻辑均未改变。

## 验证

- 新增回归用例：`internal/pool` 的页内冷/暖号选择、页外暖号不越页、绑定落库 4 项；`internal/gateway/openai` 的超限与未超限会话粘性 2 项。
- 这 6 项用例在修复前的代码上会失败（超限对话两轮分别落到 `token-1` / `token-2` 两个账号），修复后通过。
- Windows：`go vet ./...` 与全包 `go test ./... -count=1 -p=1` 通过。
- 这是调度行为修复，未做新的性能基准；请以各实例自己的 token 加权缓存命中率对比。

## 升级说明

- 无数据库或存储迁移，可直接替换二进制 / 镜像；回滚即换回旧版本。
- 若希望恢复旧行为（超限对话每轮轮转），把 `WB_AFFINITY_MAX_MSGS` 调小即可；设为 `0` 表示永不分页（全程钉住同一账号），把 `WB_AFFINITY_PAGE_SIZE` 设为 `1` 亦同。
- 观察缓存效果请用 token 加权口径：`sum(cached_tokens) / sum(prompt_tokens)`。按请求数统计「`cached_tokens = 0` 的比例」会把每个新会话的第一轮和所有短 prompt 都算进去，不同实例的流量结构不同，不能直接横向比较。

## 下载与校验

提供 `wb2api-linux-amd64`、`wb2api-linux-arm64` 和各自的 `.sha256` 文件，均内嵌 Web 面板与版本号。下载对应架构的二进制及校验文件后执行：

```bash
sha256sum -c wb2api-linux-amd64.sha256
chmod +x wb2api-linux-amd64
```

arm64 用户将文件名替换为对应架构。正式资产由仓库 GitHub Actions release 工作流构建，不使用开发机临时二进制。

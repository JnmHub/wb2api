# v2.4.0 — 高并发性能与可靠性更新

本版在 v2.3.8 基础上完善高并发调度、可靠用量记账和三协议输出链路，保留 Chat Completions、Responses、Messages、工具调用、会话亲和、固定账号、配额与可选 TPS 限速。

## 更新要点

1. **首字与流式输出优化**：修复缓冲区、半行数据和 TPS 等待拖延首字的问题；空闲超时只计算实际上游读取，减少误取消；Responses 减少重复 JSON 解析，并限制未闭合 DSML 的推测性缓冲。
2. **高并发调度优化**：采用有界亲和缓存、空结果缓存与同键请求合并；满载账号通过 Redis 批量容量提示筛选，再做原子准入；统一探测与等待预算，避免只等待单一满载账号。
3. **可靠记账与批量提交**：每副本独立持久化 outbox，FULL-WAL group commit 成功后才确认；稳定事件身份与事务 receipt 支持重启幂等重放。drop/sample 仅削减可选请求明细，不采样已接受的 token、credit 和请求计数；PG 批量预聚合降低写入往返。
4. **热路径和多副本一致性**：剩余额度权重改为后台不可变快照；PG 账号增量同步保留在途状态；Redis 租约使用服务端时间，所有权丢失时取消请求；亲和版本防止旧异步写跨副本复活。
5. **安全与生命周期修复**：阻止结果不明的已发送 POST 自动重放，公开错误不再回显原始上游诊断；修复动态 Key 并发、启动设置快照、今日用量恢复和退出时的记账顺序。
6. **慢客户端与可观测性**：三协议流式/非流式实际写入和 Flush 独立限时；HTTP/2 慢流不拖垮同连接兄弟流；新增上游 TTFT、客户端成功刷新、准入/Key 等待与取消延迟，保留旧指标字段。

## 验证与性能结果

- Windows：`go vet ./...`、全包测试通过。
- Linux：启用真实 PostgreSQL 16 / Redis 7 的全包 `-race` 测试通过。
- 20 次实际子进程强杀恢复、12 个真实 HTTP/2 隔离 race 子场景通过；前端类型检查、21 项测试与 production bundle 构建通过。
- 本地配置真实 PG、Redis 和持久化记账的短测（并发 100）：Chat 客户端 TTFT p50/p99 为 **46.20/51.40 ms**，同轮直连为 **41.03/42.21 ms**；输出吞吐分别约 **24,546/24,388 token/s**。
- 这是有噪声的单 gateway、固定 mock 短测，**不表示网关比直连快，也不是生产或双副本 HA 的容量保证**。

## 升级前必读

- **先备份并安排维护窗口，不要让旧用量 writer 与新版混跑。** 新 facts/baseline 与账号同步触发器迁移可能持锁；停止旧副本后再开放新版写入。
- **每副本必须保留独立、稳定、可写的 outbox。** HA Compose 已配置独立卷，镜像为非 root 用户准备 `/outbox` 权限。不要共用路径、复制运行中的 outbox、回退旧 outbox 快照或删除 receipt；不要通过 `docker compose down -v` 升级。
- 新默认：共享 Redis 限流不可用时**拒绝新准入**。确需旧的本地回退可显式设置 `WB_SHARED_LIMIT_FAIL_OPEN=1`，但故障期间不保证集群并发上限。
- 默认 outbox 待投递 payload 预算为 256 MiB（`WB_USAGE_OUTBOX_MB`）；SQLite WAL、索引与历史数据另占空间。监控本地 durability、pending、sink 错误和真实磁盘余量。
- 默认每次实际下游写入/刷新超时为 30 秒（`WB_DOWNSTREAM_WRITE_MS`），不包含主动 TPS 等待；负数可关闭。
- 已接受完成事件可重放不等于上游调用与本地记账是同一事务；成功 Record 前崩溃仍有窗口。异步已交付汇总也**不是事务式集群硬配额**。

## 下载与校验

提供 `wb2api-linux-amd64`、`wb2api-linux-arm64` 和各自的 `.sha256` 文件，均内嵌 Web 面板与版本号。下载对应架构的二进制及校验文件后执行：

```bash
sha256sum -c wb2api-linux-amd64.sha256
chmod +x wb2api-linux-amd64
```

arm64 用户将文件名替换为对应架构。正式资产由仓库 GitHub Actions release 工作流构建，不使用开发机临时二进制。

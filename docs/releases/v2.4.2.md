# v2.4.2 — 每日任务独立排程

本版把「每日任务」从"跟着任意整点巡检顺带跑"改成**每类任务按自己的整点表执行**，并把国际版每日活跃对话（每日对话任务）提升为独立的排程项，面板可以单独设置时间。

## 修复内容

1. **每日任务有了自己的整点表**：`checkin`（国内签到）、`report`（国内活跃上报）、`daily_chat`（国际版每日活跃对话，桌面 "Hi" + 网页会话）三项各自独立，默认都是 9 点与 21 点；`keepalive`（Token 保活巡检）仍是 22 点。
2. **不再被别的整点拖着跑**：此前巡检按所有网格的并集触发（9、21、22、次日 1 点各一轮），而签到、活跃上报、每日对话不看当前是不是自己的点，凌晨 1 点那轮也会再试一遍。现在只有到了自己的整点（或当天最后一个整点之后的补跑）才执行，减少对上游的重复调用。
3. **失败当天可补跑**：错过最后一个整点后，当天后续巡检仍会把"今天还没做"的任务补上；已经成功过的任务由"今日已做"标记拦住，不会重复请求。
4. **手动巡检与启动巡检不受整点限制**：「立即巡检」和进程启动那次巡检直接执行全部每日任务（补签语义，晚上线也能补上当天），仍受"今日已做"标记与风控跳过规则约束。
5. **面板**：任务页的"后台任务"卡片拆成三个输入框（国内签到/活跃上报、国际版每日活跃对话、Token 保活），可分别设置整点。

## 保持不变的语义

- 风控受限账号、被暂停区域、停用账号、Token 为空仍然是**直接跳过**，不会被这些任务触碰。
- 每日任务成功后才写"今日已做"时间戳；失败不写，因此当天还能补跑。
- 账号之间仍然随机错峰 2–5 秒，同一账号的连续任务间隔 1 秒，避免突发请求。
- 已有配置无需迁移：`schedule` 里缺少 `report` / `daily_chat` 时自动取默认值。

## 验证

- 新增调度器测试：网格内执行、网格外不执行、最后一个整点之后补跑、手动巡检忽略整点、`daily_chat` 独立于 `checkin`、`dueInGrid` 边界值。
- `go vet ./...`、`go test ./... -count=1`（Windows）通过；前端 `tsc -b --noEmit` 与 vitest 通过。

## 升级说明

- 无数据库或存储迁移，直接替换二进制 / 镜像；回滚即换回 v2.4.1。
- 想让每日活跃对话更靠前或靠后：面板任务页或 `PATCH /api/v2/scheduler` 的 `schedule.daily_chat` 改成需要的小时（`"3, 15"` 这类字符串或数组均可）。
- 只想跑签到、不要国际对话：把 `schedule.daily_chat` 设为不触发的小时即可（例如与 `keepalive` 错开）。

## 下载与校验

提供 `wb2api-linux-amd64`、`wb2api-linux-arm64` 和各自的 `.sha256` 文件，均内嵌 Web 面板与版本号。下载对应架构的二进制及校验文件后执行：

```bash
sha256sum -c wb2api-linux-amd64.sha256
chmod +x wb2api-linux-amd64
```

arm64 用户将文件名替换为对应架构。正式资产由仓库 GitHub Actions release 工作流构建，不使用开发机临时二进制。

# v2.4.5 风控只封账号，不再封网关

这一版改的是**风控命中后的处置方式**：以前一个账号被上游限制，可能导致整个区域暂停派发；现在只给这个账号打标签，其余账号照常服务。

## 问题

上游返回 `403 / code 11140`（账号存在异常行为）时，旧版默认做两件事：

1. 给命中的账号打标签（`restrictedUntil`，约 2 小时）——这一步是对的；
2. 同一区域 15 分钟内出现 ≥2 个不同账号受限，就**暂停整个区域派发** 1800 秒，期间所有客户端拿到：

```
上游风控已限制本区域账号（403 / code 11140，账号存在异常行为）。网关已暂停派发 564 秒…
```

一个坏账号拖停整个池，实际体验是“网关被锁了”，很难受。

## 现在的默认策略

- **命中的账号**：打标签（`restrictedUntil` = 现在 + 2 小时，写回账号记录，重启后仍然生效，面板可见），选择器从此不再选它；
- **当前请求**：继续用其它账号完成，客户端拿到正常回复，而不是 403；
- **整个区域**：**不暂停**。`WB_RESTRICTION_HOLD_SECONDS` 默认从 `1800` 改为 `0`。

也就是说：坏几个账号，就少几个账号的容量，网关本身不停。

## 变更细节

| 项 | 旧默认 | 新默认 | 说明 |
| --- | --- | --- | --- |
| `WB_RESTRICTION_HOLD_SECONDS` | `1800` | `0` | 区域暂停秒数；0 = 关闭 |
| `WB_RESTRICTED_403_ROTATE_MAX` | `0` | `2` | 一次请求撞到受限账号后还能换几个账号继续 |

`WB_RESTRICTION_WAVE_MIN`（默认 2）和 `WB_RESTRICTION_WAVE_WINDOW`（默认 900 秒）保留，只在把暂停重新打开时生效。

想恢复旧的“连坐保护”（宁可整体停下也不让池子被扫）：

```yaml
environment:
  WB_RESTRICTION_HOLD_SECONDS: "1800"
  WB_RESTRICTED_403_ROTATE_MAX: "0"
```

## 客户端提示语

暂停关闭时不会再出现上面那段“暂停派发”文案。若你手动把暂停打开，文案仍然是网关自己生成的（不是上游原文），秒数等于剩余暂停时长。

## 验证

- `internal/risk` 新增用例：默认配置下连续 4 个账号受限都**不会**暂停区域，`HoldRemaining` 恒为 0；显式设置 `WB_RESTRICTION_HOLD_SECONDS=600` 时恢复旧行为。
- `internal/gateway/openai` 新增端到端用例：account-0 返回 `403 11140` → 请求换到 account-1 **返回 200**，无 `Retry-After`、`RiskHold` 为 0、受限账号被持久化打标签、下一次请求不再选中它。
- 旧用例改为显式开启“不换号”模式后再断言（`WB_RESTRICTED_403_ROTATE_MAX=0`），保留对 opt-in 行为的覆盖。
- `go vet ./...`、`go test ./... -count=1 -p=1` 全量通过。

## 升级说明

- 无需改配置、无需数据库迁移；重启后默认即为“只封账号”。
- 已经处于区域暂停状态的内存状态会随重启消失；账号上的 `restrictedUntil` 标签仍然保留，到期自动恢复。
- 面板账号列表可以直接看到哪些账号被打了标签（`restricted_until`）。

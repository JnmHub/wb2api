# v2.6.3 — 华为渠道能看积分余额了，流内错误不再被当成功

v2.6.0~v2.6.2 我一直说「上游没有余额接口」。这句话是错的：余额在
`GET /snap-manager/v1/statistics/plugin`，只是不在我之前逆向到的那条路径上。
参考 [ProvidersPlugin/Agent2Providers](https://github.com/ProvidersPlugin/Agent2Providers)
的 `codearts/balance.rs` 找到并实现了。

顺带修掉一个更危险的：**华为把失败塞在 HTTP 200 的 SSE 帧里**，我们之前认不出来。

## 积分余额

`metadata` 里每个账号现在有真实余额（实测三个账号）：

```
剩 500 / 500 积分（Trial，2026-12-18 重置）
剩 4500 / 4500 积分（Trial，2026-12-18 重置）
剩 4499.34 / 4500 积分（Trial，2026-12-18 重置）
```

面板「积分」列与账号详情读的就是这个，与 WorkBuddy 的口径一致。

**端点**：`GET {snap-access}/snap-manager/v1/statistics/plugin`
**签名**：只覆盖 `Accept` / `X-Language` / `plugin-name` / `plugin-version` 四个头
（多一个 `Content-Type` 签名串就不同，有单测钉住）

**解析要点**（都是参考实现踩过的坑，逐条实现）：

| 情况 | 处理 |
| --- | --- |
| `show:false` 的指标行 | 跳过（上游用它 retire 指标，值常带 `-1` 哨兵） |
| `value < 0` | 不当作百分比（-1 表示"不适用"） |
| `package_token_amount = 1` | 是占位形状，不当作配额显示 |
| **汇总行 `usageTotalPackageCredit`** | 与分项行之和相等时**只取分项**，否则余额翻倍 |
| 分项和 ≠ 汇总 | 两边都算（宁可多算一笔，不凭猜丢掉真实的钱） |

指标中文名照抄上游对照表（`usageTokenChatMessages` → 对话 token 额度 等），
认不出的保留原名——猜名字会全错。

**入口**：账号行动作 `credits`（面板「刷新积分」）与批量 `refresh_credits`
都按渠道分派到余额；与签到同一套「临期先续期、0602 再重试」。

## 流内错误：HTTP 200 也可能是失败

华为把「福利额度用尽」这类失败放在 **HTTP 200 的 SSE 体**里：

```
data: {"error_code":"InferHub.4291.200","error_msg":"insufficient quota"}
```

以前只认 OpenAI 形状的 `{"error":{...}}`，于是这种流会被当成「成功但一个字没答」，
**且不会换号**。现在 `upstreamSSEError` 也认裸 `error_code` 信封：空 / `0` / `0000` /
`success` 不算故障，其余（`InferHub.*`、`TM.*`）一律按失败处理并带上错误码。

## 测试

```
ok  upstream/codearts   统计解析（汇总去重、show:false、-1 哨兵、占位 1 token）、
                        聚合（重复/不重复两种）、四头签名、BalanceView
ok  codeartsync         余额落盘到 Credits

ok  gateway/openai      流内 error_code 信封识别（含成功码白名单）
```

真机验证（三个真实账号）见上，余额与重置日期都来自上游。

## 还没做的（来自同一个参考实现，按风险排序）

1. **会话心跳**：上游每账号只允许 3 路并发，第 4 路回 `TM.00001041`；它要求对话前
   `PUT /snap-manager/v1/chat-session/heartbeat?status=busy` 登记一个 32 位 hex 的
   `user-session-id`，对话请求带同一个头，结束 `status=idle` 注销。不实现这套，
   连续快发会稳定撞 400 —— 我们的默认并发正好是 3，处在边界上
2. **工具名 64 字符上限**：超限回 `InferHub.001001017.413`（收请求前预校验）
3. **体积门**：推理后端 ~6 MiB 回 `InferHub.001001005.400`，API 网关 ~12 MiB 回
   `APIG.0201`；撞过就记住这条线，同尺寸请求直接绕开该账号
4. **福利开关**：先查 `{base}/v1/benefit-gateway-config`，开了才去网关取模型；
   我们目前直接打网关，没资格的账号会拿到 4000
5. **签到回读确认**：claim → confirm 之后再读一次列表二次确认，并限制每账号每天
   6 次、间隔 10 分钟

这五项会作为后续版本处理，不做静默降级。

## 升级说明

- 无需迁移；账号的 `credits` 字段会在下次「刷新积分」或后台巡检时写入
- 余额与签到领取量是两回事：前者是套餐剩余，后者是某次活动领到多少

# v2.4.9 — 模型后备链覆盖「选不到号」

v2.4.8 的后备链有一个盲区：它把「这个模型在所有账号上都不行」判断得比选号本身窄，
于是**模型被人工禁用、或账号池被风控清空**这类最常见的故障里，请求会直接 503，
后备链一次也不会触发（线上 48 小时 0 条 fallback 记录就是这么来的）。

## 修复

- 后备链的可用性判断改为与选号完全一致的口径（`Account.HealthReady`）：账号停用、
  上游风控、余额耗尽、各类冷却、**人工禁用的模型**、模型级 429 阶梯、6004 额度窗口、
  权限缺失，任一条命中就视为「这个账号服务不了这个模型」。
- 因此当 `no usable account` 即将发生时，网关会先尝试后备链的下一段；只有链上每一段
  同样不可用（或被封禁名单过滤）才返回 503。
- 并发饱和仍然不算「不可用」：池子忙是瞬时的，不会因此消耗一段链。

## 回归测试

- `TestModelChainAdvancesWhenTheModelIsDisabledOnEveryAccount`：A 被风控 + B 人工禁用该模型，
  请求落到 `space-bunny` 并 200；修复前该用例复现出与线上完全相同的 503 文案。
- `TestModelChainAdvancesOnCoolingAccountsWithNoUsableAccount`：全池该模型处于冷却窗口时同样推进。
- 原有 5 个链/共享窗口用例保持通过（「有账号能服务就不推进」「跳过链上同样不可用的模型」
  「返回体回写请求名」）。

## 升级说明

- 无需改配置；已有 `model_fallbacks` 立即生效。
- 语义仍是阶段式：只有当前模型彻底不可用时才换，链最多 8 段，返回体 `model` 仍是客户端请求的名字。
- 如果你此前因为这个盲区把 `model_fallbacks` 删掉了，可以重新配上。

## 下载与校验

发行版附带 `wb2api-linux-amd64`、`wb2api-linux-arm64` 与各自的 `.sha256`；先校验再运行：

```sh
sha256sum -c wb2api-linux-amd64.sha256
```

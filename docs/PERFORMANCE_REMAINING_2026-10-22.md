## 1. 已实现的剩余项目

### 1.1 持久化用量与不采样的计费事实

- `Record(Event) error` 成功返回前，完成本地 SQLite WAL、`synchronous=FULL` outbox 提交；远端 PostgreSQL 故障不再直接丢掉已接受事件。
- 本地专用 group committer 将已经排队的事件合并提交，无主动 linger；最多 256 事件 / 4 MiB 编码变体，单个超限事件按有界例外处理。所有成功确认都在共享事务提交成功之后，不通过降低同步等级提速。64 个预排队事件的确定性回归只需 1–2 次 FULL 事务。
- 本地准入通道最多 64 事件，默认 full/minimal 变体合计至多 32 MiB，另有有界在途批次、carry 和一个串行编码者；不是“全部内存仅 4 MiB”。准入超时不伪装成已接受，FIFO Flush 屏障报告此前本地持久化失败，Close 会解析所有已入队确认再关闭句柄。
- 每个副本使用独立、稳定的本地 outbox 路径和 OS 排他锁。事件身份为随机 source ID 加单调序号，重启后保留。
- sink 事务同时写入 `usage_facts`、日/小时汇总、可选请求明细和 source 高水位；确认提交后才删除本地事件。提交结果不确定时重放相同身份，不重复累计。
- drop/sample 只影响可选请求明细，不采样已经接受的 token、credit 和请求计数。精确时间范围查询、余额估算等改读无采样事实；历史汇总基线保留，重建不再从已采样明细推断完整用量。
- outbox 有待投递有效载荷预算（默认 256 MiB）、单事件限制和有界批量加载；本地不可写或容量满可阻止新的付费准入，远端投递错误与本地就绪分开展示。准入 Ready/Health 读取原子快照，不在之前请求的 Record/fsync 锁后排队；状态在本地提交、确认删除、失败和关闭边界发布，仍不代表容量预留。
- PostgreSQL 每批最多 256 事件，事实/明细多行 INSERT，日/小时维度预聚合并排序后批量 UPSERT，最多四条数据 INSERT，外加固定事务、锁和 receipt 开销。保留跨副本 advisory lock，减少锁内网络往返，而不是简单加 worker 或移除防死锁保护。
- Today 启动快照合并 sink 已交付汇总与本副本尚未交付事件，通过一致性 receipt 快照避免重复；过期的昨日事件不再回滚今日内存计数。

实现入口：[outbox](../internal/usagedb/outbox.go)、[投递与确认](../internal/usagedb/retry.go)、[PG 批量写入](../internal/usagedb/pg_batch.go)、[完整持久化契约](../internal/usagedb/DURABILITY.md)。

**不能承诺的边界：** readiness 不是空间预留；上游已经计费、但进程在 Record 成功之前崩溃，仍无完成事件可重放。硬件必须正确履行 fsync。配额守卫读取的是已交付 sink 数据，不包括各副本待投递事件，因此不是事务式集群硬配额。启动/迁移仍要求 sink 可用。Today 的启动补偿不等于自动跨副本实时对账。

### 1.2 饱和准入不再逐个串行试探全池

- Redis occupancy 只是调度提示：20 ms 缓存、同批查询合并、512-key 分段 pipeline、最多 8,192 条本地缓存；读取使用 Redis 服务端时间。
- 筛掉明显已满账号后，仍必须通过原子共享 Acquire 和本地槽位，提示从不授予准入。
- 同一个 account admission budget 覆盖初始选择/探测与后续等待；旧接口不支持独立 probe deadline 时保留请求 lease 生命周期，并拒绝、释放迟到的成功结果。
- 全满提示会做一次强制刷新，即使不配置排队，也不会被短期旧缓存一直拒绝；多候选等待轮询整组，固定账号请求不跨账号绕过限制。
- 回归夹具中，100/1,000 个全部已满账号使用至多两次批量 hint 调用、零次逐账号原子试探。真实 Redis 的 pipeline 数量仍随 `ceil(N/512)` 增长，不能称为无限规模 O(1)。

实现：[准入预算与提示](../internal/gateway/openai/capacity.go)、[共享 occupancy](../internal/platform/redisx/capacity.go)、[饱和回归](../internal/gateway/openai/capacity_test.go)。

### 1.3 热路径快照与账号增量同步

- RemainingPriority 的请求路径只读取不可变原子快照，不再持锁查询过去 26 小时数据、扫描事件文件、复制整份权重表。刷新在后台合并执行，有超时、失效版本和停止/等待机制；冷启动可以暂不应用这项建议性权重，不更改账号健康/权限条件。
- 限流观察事件使用有界保留和异步落盘；面板需要新鲜 payload 时走独立刷新接口，失败保留最后有效结果，不制造零用量。
- PostgreSQL 账号轮询改为事务提交顺序的版本时钟、按 UID 合并变化和删除 tombstone；保存后只重载对应账号。无变化不重建全池，也不清空调度偏好缓存。
- 保留账号运行时对象、占用槽位、冷却状态和本地信用扣减；删除/撤销会禁用已被请求持有的旧对象。全量快照只用于启动或游标恢复。
- 同步触发器覆盖直接 SQL 更新、删除和 TRUNCATE；重复读取、回滚、迟提交、删除后重插、损坏记录和一致性快照均有回归。

实现：[后台估算快照](../internal/usageest/snapshot.go)、[只读权重](../internal/pool/remaining_snapshot.go)、[PG 变化读取](../internal/store/pgaccounts/sync.go)、[保留运行态的增量应用](../internal/pool/sync_incremental.go)。

**保留的安全取舍：** settings 到期刷新仍可以等待合并后的同步读取，避免把撤销与权限刷新改成无限期旧缓存；每日配额扫描也没有声称完全脱离请求路径。其并发读取合并和同日最后有效值保护由第一批完成。PG 启动已成功读取的 settings 直接初始化不可变快照，防止随后冷读取失败产生空文档、错误关闭 API-key 鉴权；回归验证失败刷新保留已知 Key，主动更新立即生效。

### 1.4 Redis 故障策略、租约所有权和亲和版本

- 配置共享限流时默认 fail closed：后端不可用拒绝新准入。`WB_SHARED_LIMIT_FAIL_OPEN=1` 可显式保留可用性优先的本地回退，但故障时不保证集群并发上限。
- Acquire/renew 和 occupancy 使用 Redis server TIME，避免副本时钟偏移误判所有者；相同活跃 member 的重复 Acquire 幂等。
- 独立 watchdog 只接受及时确认的续租。所有者不存在、确认窗口耗尽或 ACK 太晚时取消请求；续租 RPC 卡住不能无限延长本地所有权。
- release 停止并等待续租/丢失回调后再删除 member；loss callback once-only。真实 Redis 代理丢弃续租响应的测试验证：服务端续租其实成功，也不会凭未确认结果继续无限占用上游。
- 亲和更新使用原始观察的随机 epoch、generation、服务端签发时间；Demote 之后旧异步 Bind 不能跨副本复活被淘汰绑定。worker 不重新借用新版本掩盖旧写。
- 选择阶段不再发布亲和；gateway 在 HTTP 200 接受边界发布观察绑定，启用首输出保护时还要通过该保护。HTTP 200 后立刻发生 SSE 错误仍可能保留绑定，这不是“已成功生成内容”的保证。

实现：[租约 watchdog](../internal/platform/redisx/lease_watch.go)、[故障代理回归](../internal/platform/redisx/lease_outage_test.go)、[版本化共享亲和](../internal/platform/redisx/affinity.go)。

**边界：** 请求取消不是外部资源的分布式 fencing token；进程被暂停超过 TTL 时不能保证实时执行取消。网络分区时本地缓存仍只是建议，失败的 Demote 不能承诺跨副本可见。回调只允许发出取消信号，不可同步调用会等待自身的 Release。

### 1.5 实际延迟、慢客户端和关闭顺序

- 保留旧 TTFT 字段，新增 `UpstreamTTFT`、`ClientTTFT`、`AdmissionWait`、`KeyWait`、`QueueWait`、`CancelLatency`；接口和请求明细透传。
- 上游指标从每次实际 dispatch 到首次语义输出读取，不混入选账号、等待或重试睡眠；账号反馈使用该指标。Responses 后续调用按实际 attempt 重置。
- 流式 ClientTTFT 到成功完成首次语义 Flush，不是响应头/role 帧；非流式记录完整 JSON 文档成功 Flush 的时间。均不谎称浏览器已经收到。取消指标记录观察取消到终结的时间，正常 defer 清理不制造取消样本。
- 三协议流式及成功非流式响应，每次实际客户端 Write/Flush 独立设置默认 30 s deadline，主动 TPS 等待与上游空闲不消耗该预算；HTTP/1、HTTP/2 可用，未暴露 ResponseController deadline 的包装器只能保留旧行为，不提供虚假超时保证。非流式发送失败保留已发生用量、只记一次 client_aborted，不重新生成或追加第二个错误响应。
- 关闭先停止 HTTP 准入并等待 handler（含终结 OnUsage），超时取消/关闭连接；再停并等待后台任务、估算刷新、导入和观察落盘，最后关闭用量数据库及共享池。避免请求结束时写入已经关闭的账本。

实现：[指标定义](../internal/gateway/openai/latency.go)、[写入 deadline](../internal/gateway/openai/downstream.go)、[关闭屏障](../cmd/hub/lifecycle.go)。不配合取消的 handler/OS I/O 可能延长退出；不能在继续使用数据库时安全强行关闭并声称账本完整。

## 2. 验证证据

### 2.1 已完成的定向故障验证

- Linux Go 1.27.1、CGO 开启、GCC 12.2；独立 PostgreSQL 16、Redis 7 网络，不映射生产端口，不改动已有服务。
- Redis 全包 race 通过；加强断言后的真实 Redis 续租黑洞测试再通过，覆盖已续租但丢响应、所有权删除、迟到 ACK、重复 loss、release 后无迟取消和时钟偏移。
- 真实子进程强杀恢复 race 测试重复 10 次、两个窗口共 **20 次强杀**：每个子进程启动 17 个并发 Record，全部成功返回后才发出可强杀握手；覆盖已接受但未送达 sink、sink 已提交但本地删除确认失败。重复重启核验每个事件、汇总、精确采样明细身份、receipt、source 和下一序号一致。不是硬件断电或 PostgreSQL 进程崩溃测试。
- group commit 定向测试重复 10 次通过，真实 PG 用量整包 Linux race 通过；覆盖共享提交前不提前确认、局部容量拒绝、事务失败解析所有等待者、Flush 的有序失败传播以及满队列 CloseTimeout 取消/排空。
- 真实 TLS HTTP/2 同一 TCP 连接测试在 Linux race 下重复 3 次、12 子场景通过：8 MiB 慢流超过 stream window，deadline 或取消仅终止该流，兄弟流仍成功；流式/非流式都释放共享、账号与 Key 槽，付费用量只记录一次。
- 三协议第一语义帧、半行阻塞、TPS 等待与 idle 区分、慢读/取消、歧义 POST 不重放、动态 key 限制、固定账号及全满预算均纳入回归。

#### 中间复测 run2：Ready 不再等待 fsync 锁

复核发现新请求的 Ready 曾通过 RLock 等待之前完成请求的 Record 独占锁，静态机制会把终结阶段 fsync 间接放回其他请求的首 token 路径。改为原子不可变 readiness 快照，并增加持锁条件下仍能完成 Ready/Health 的同步回归后，按同样参数保留独立 run2；本次额外记录服务端延迟与 Record 耗时。

| run2 路径 | 客户端语义 TTFT p50 / p95 / p99 (ms) | 全响应时长 p50 / p99 (ms) | 请求/s | 输出 token/s |
|---|---:|---:|---:|---:|
| 直连 | 40.945 / 41.785 / 43.124 | 140.081 / 174.689 | 685.40 | 27,416.0 |
| 配置后端的 Chat | 44.479 / 49.483 / 50.734 | 148.220 / 297.488 | 488.79 | 19,551.8 |

全部输出和 600 条账本事实再次核验通过。600 条服务端事件的 p50 / p95 / p99：

- 上游语义 TTFT：40.320 / 41.806 / 42.861 ms。
- 准入加 Key 等待：1.033 / 6.790 / 7.838 ms。
- 同步 Record：12.135 / 94.280 / 105.333 ms，包含锁等待及本地持久化整体，不是单独 fsync 时间。

- 上游语义 TTFT 为 40.399 / 42.166 / 43.486 ms；准入加 Key 等待为 2.233 / 6.644 / 7.358 ms。客户端首字较同轮直连 p50 增加约 5.17 ms，p99 增加约 9.19 ms。
- **该夹具的完整配置吞吐已处于直连同一量级，但不宣称 gateway 比直连快。** 直连第二轮完整响应 p99 为 230.720 ms，而第一/三轮约 163.783 / 162.318 ms；短时计时器、共享主机和容器噪声影响 pooled 吞吐，不能用倒置结果计算稳定加速比例。
- 这是保留全部测量结果的短时对照，不是因果消融或生产 SLO 证明。run2/run3 的 Record 尾部下降是观察结果，group commit 的确认与事务数机制另由确定性测试证明。

本轮是单 gateway、短时、Linux 容器内本地 mock 测试，不覆盖双副本 HA、外部网络/TLS、长稳态、真实模型与计费。方法、逐轮结果、原始样本及缓存条件见本地归档 `REMAINING_BACKEND_COMPARISON.md`（未随源码分发）。真实部署仍需按目标 SLO 验收，而不是仅依据功能测试上线。

## 3. 部署与升级检查清单

1. **先备份、隔离演练，不能直接滚动混跑旧用量 writer。** 新 facts/baseline 假设旧 writer 已停止；旧 writer 会绕过事实表并破坏重建语义。PG BIGINT 与同步触发器迁移可能持锁，大表需维护窗口。
2. 每副本独占持久化 outbox。HA compose 已分配两个独立卷；不能共享路径、复制运行中的 outbox、回退旧快照或删除 receipt。升级不要 `down -v`。
3. 256 MiB 是待投递 payload 预算，不是严格物理磁盘上限；WAL、索引、freelist 和长期 sink 历史另占空间。监控本地 durability、pending、sink 错误和实际磁盘。
4. 确认 fail-closed 是本次有意默认变化；需要旧的故障本地回退时显式开启，并接受集群上限不再可靠的代价。
5. 本地完成事件成功持久化不等于同步集群硬配额。严格预算场景另需上游前的持久化预算预留/结算协议，不能靠这次异步汇总补成保证。
6. 从新版 SQLite 或只有历史汇总的旧库迁移，先停源并排空其 outbox，再执行离线完整快照导入；不能把它当连续增量复制。详细规则以[持久化契约](../internal/usagedb/DURABILITY.md)为准。
7. 先在目标部署用相同模型、请求、连接复用、并发和输出长度做直连/单机/HA 对照，再决定上线。保留三协议、工具调用、分页/固定账号、撤销、TPS、配额、错误和恢复验收。

## 4. 复现入口

源码内包含功能、并发、崩溃恢复、租约故障及 HTTP/2 回归测试。Go 1.27.x、Linux CGO/GCC 可执行：

```bash
go vet ./...

```

需要真实后端测试时，设置 `WB_TEST_POSTGRES_DSN` 与 `WB_TEST_REDIS_ADDR` 指向专用测试实例；这些测试可能修改或清空测试库，**禁止使用生产凭据或生产数据库**。仓库 CI 的独立服务提供可重复的后端验证环境。

本文所引用的开发期原始日志、mock 性能 overlay 和逐请求采样保存在未随源码分发的本地证据目录，数值与限制已在正文完整摘要；它们不属于发行版运行依赖。最终 Actions 日志可在仓库的 CI / release 页面查看。专用本地测试容器已停止，未操作已有业务服务。
